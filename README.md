# Jarvis Installer

[English](README.en.md)

Локальная база инструкций, памяти и проектов для ИИ-агента. Пользователь выбирает
нужные модули, агент задаёт несколько вопросов и создаёт отдельную папку с
правилами. Одна база подходит для личных дел, разработки и дизайна; контекст и
разрешения этих областей остаются раздельными.

**Версия 0.4.0 — локальный установщик.** Это не отдельная модель и не постоянно
работающий сервис. Изменения происходят во время работы подключённого агента.
Установка не меняет глобальные настройки, существующие проекты и аккаунты.

Агент распределяет значимую память по тематическим разделам и поддерживает
отдельное состояние текущих дел. Команда `note --section` сохраняет запись
в выбранном разделе; без параметра остаётся прежний `knowledge/personal/notes/`.
Классификацию выполняет агент по правилам, а не отдельный автоматический сервис.
Реестр проектов хранит
адреса и точки входа; автоматической миграции существующих проектов нет. Python требуется заранее: bootstrap пока не устанавливает его.
Каждая отправка изменений этого репозитория выполняется только по явному
указанию владельца; автоматической публикации нет.

## Начать

Нужны Python 3.10+ и агент, который умеет читать и создавать локальные файлы.
На Windows может потребоваться команда `py -3` вместо `python3`. Отдельная
установка библиотек, Node.js или утилит управления компьютером не нужна.

Скачайте репозиторий и попросите агента:

> Прочитай bootstrap/SKILL.md в папке Jarvis Installer. Помоги установить базу
> в отдельную папку и выбери со мной необходимые модули.

После установки подключите `AGENTS.md` новой базы к инструкциям нужного
приложения или проекта. Bootstrap предложит ссылку; изменение существующих
инструкций выполняется только по вашему поручению. Новый чат должен реально
загрузить эту точку входа; одной установки для обнаружения базы недостаточно.

Агент предложит выбор с галочками, если его приложение поддерживает такие
формы. Иначе он предложит номера вариантов. Поддержка форм зависит от приложения;
консольный установщик выводит данные для вопросов, а не рисует собственный UI.
Выбор «общая база» означает одну папку для нескольких ваших проектов. Это не
установка в системные каталоги и не доступ других пользователей.

Для ручной проверки скопируйте `templates/answers.example.json`, отредактируйте
ответы и выполните из папки дистрибутива:

```sh
python3 bootstrap/scripts/jarvis.py catalog
python3 bootstrap/scripts/jarvis.py plan --target /absolute/path/my-jarvis --answers /absolute/path/answers.json
python3 bootstrap/scripts/jarvis.py install --target /absolute/path/my-jarvis --answers /absolute/path/answers.json
python3 bootstrap/scripts/jarvis.py doctor --root /absolute/path/my-jarvis
```

Путь должен вести в новую/пустую папку либо в существующую установку этого
формата. Чужую непустую папку установщик не перезапишет. При обновлении изменённые
вручную системные файлы вызывают конфликт, который нужно сначала разрешить.

## Что окажется у пользователя

```text
my-jarvis/
  AGENTS.md                   точка входа для агента
  config/
    instance.json             ваши ответы, согласия, выбранные модули
    installation.json         версия и контрольные суммы системных файлов
  core/                       структура, контекст, память, разрешения, обновление
  bootstrap/                  установочный навык и локальные команды
  modules/                    только выбранные модули; local/ для своих навыков
  presets/                    варианты начального выбора
  adapters/                   особенности приложений-агентов
  templates/                  шаблоны для новых записей и проектов
  .agents/skills/              производные копии навыков для обнаружения хостом
  knowledge/personal/         текущие личные факты и предпочтения
  projects/<id>/              карточки; материалы по назначениям storage
  assets/                    обычные вложения
  inbox/                     непроверенные входящие, исключены из Git
  local/                     служебная очередь, исправления, локальные секреты
```

Архив появляется только после выбранного импорта или сохранения доступного чата: `archive/conversations/` для
личных источников или `projects/<id>/archive/` для встроенных проектов режима folder.
Архив проекта schema 2 хранится в назначенном assets/conversations; legacy использует прежний explicit binding. Папка `vault/`
возможна после отдельной настройки шифрования; установщик её не шифрует.
Ненужные разделы и файлы с вымышленной биографией не генерируются.

В самом репозитории те же шесть каталогов содержат исходные правила, все
доступные модули и шаблоны. Дополнительно здесь есть `tests/` и `reports/`.
Пользовательская установка содержит выбранные модули и собственные данные.
Чтобы добавить отсутствующий модуль, нужен полный дистрибутив.

## Центральная и локальная установка

`location_mode` определяет расположение экземпляра. Знания каждого проекта/группы schema 2 независимо размещаются глобально, локально или по разделам. Проект может не иметь исходников.

```sh
python3 bootstrap/scripts/jarvis.py projects --root /absolute/path/my-jarvis create --id project-a --title "Project A" --kind project --purpose "Project purpose" --storage jarvis
python3 bootstrap/scripts/jarvis.py projects --root /absolute/path/my-jarvis resolve --id project-a --section specs --create
python3 bootstrap/scripts/jarvis.py projects --root /absolute/path/my-jarvis rules --id project-a
```

Карточка project.json — владелец родителя и адресов. project.md — навигация. Для локального назначения сначала зарегистрировать существующий root, затем bind нового раздела или move-section существующих данных. Отсутствующий root не создаётся и не заменяется глобальным fallback. Связанные проекты не получают чужие разрешения. Legacy schema 1 мигрирует только явно. Центральный snapshot не является резервной копией внешних разделов.

Snapshot сохраняет выбранные байты файлов и manifest контрольных сумм. Он не
подтверждает сохранность файловых метаданных, прав, временных отметок, пустых
каталогов и связей между файлами либо согласованность работающих баз данных.
Нужные метаданные, актуальное состояние и внешние хранилища резервируются
отдельным настроенным процессом с проверкой восстановления.

Старые проекты с `governance/README.md` сохраняются без автоматического переноса
и доступны через locate-project как legacy. Переключение режима с существующими
проектами требует явной миграции. Изменение одной настройки данные не переносит.
Обнаружение навыков проверяется в новой сессии приложения; ручное чтение файла
не доказывает автоматическое подключение.

## Память, архив и поиск

Память — текущие сведения с источником и датой: «обычно хочу подробные ответы».
Исправление обновляет ту же запись, а не создаёт две противоположные истины.
«Сейчас ответь кратко» относится к одному ответу и не меняет постоянный стиль.
Режимы: `on-request` — по просьбе, `auto` — устойчивые факты в согласованных
границах вместе с решениями и контекстом текущих дел, `off` — не сохранять личные заметки.
`auto` выбирается явно: общающийся агент сам записывает сведения, когда видит
обоснованную пользу для будущего общения или работы. Каждая реплика или
завершённый ответ записи не требуют. Повторная команда «запомни» не нужна; начальный
вариант — `on-request`. Разрешение вести память не разрешает остальные действия
при `autonomy=ask`. Техническая конфигурация установки
и проектные решения существуют отдельно от личной памяти.

Личные сведения хранятся в `profile`, `preferences`, `areas`, `vectors`, `events`,
`my-notes`, `context` и `inbox` внутри `knowledge/personal/`. Раздел создаётся при
первой записи. При выборе памяти установка один раз создаёт пустой
`context/active.md`: короткий указатель тем, их состояния и ссылок. Факты,
подробности тем и история хранятся отдельно. Указатель принадлежит владельцу
и сохраняется при обновлении или отключении модуля. Общий стиль ответа остаётся
в `config/instance.json.communication_style`.

```sh
python3 bootstrap/scripts/jarvis.py note --root /absolute/path/my-jarvis --scope personal --section preferences --id reading-format --kind preference --text "Предпочитаю печатные книги" --source "Владелец, текущий разговор" --explicit
```

Для исправления используется та же область, раздел и ID; для удаления —
`forget` с теми же параметрами и `--explicit`. Существующие заметки автоматически
не перемещаются. Типы `state`, `event`, `hypothesis` и `question` позволяют
отличать состояние работы, события и предположения от подтверждённых фактов.

Архив — исходный текст для проверки формулировок. Он не становится инструкцией
или подтверждённым фактом. Выбор истории независим от режима памяти:
`module_options.history.capture=provided-only` сохраняет предоставленные тексты;
`available-chats` разрешает агенту сохранять чаты, которые доступны инструментам
текущей среды. Старые текстовые настройки истории сохраняют первый вариант.
Импортируются UTF-8 `.md`/`.txt` до 2 МиБ.

После выбора `available-chats` экспорт нового фрагмента можно сохранить так:

```sh
python3 bootstrap/scripts/jarvis.py archive --root /absolute/path/my-jarvis --scope personal --file /absolute/path/chat-chunk.md --source-id codex --chat-id example-chat --date 2026-01-01
```

Источник хранится отдельно по поставщику, чату, дате и hash содержимого. Агент
отбирает новые ID сообщений и ведёт указатель покрытия и продолжения; CLI
устраняет повторы одинаковых текстовых фрагментов, а не разбирает сообщения.
Неполная выгрузка помечается как неполная. Инсталлер не подключает аккаунты,
не гарантирует доступ ко всей истории и не устанавливает фоновый сборщик.
Новый чат должен загрузить точку входа той же базы; глобальная привязка
настраивается отдельно. Память ведёт сам общающийся агент по обоснованию;
почасовой запуск или фоновый обход чатов для этого не создаются.

Поиск в v1 — обычный поиск текста в выбранной области. Семантический RAG и
автоматическое построение индексов пока не нужны и не реализованы. Формат Markdown
позволит добавить пересоздаваемый индекс позже без переноса источника истины.
Тематические исключения требуют соблюдения агентом: примитивная проверка слов
в CLI не является полноценным классификатором чувствительных данных.

## Инженерная работа с агентами

Общие правила общения, критической оценки решений, иерархии документов,
актуальности ссылок и передачи длительной работы находятся в `core/` и действуют
по выбранной области. Они не дают права на тесты, делегирование или публикацию
сами по себе. Отдельный модуль `writing` содержит экспериментальный workflow
русскоязычных технических статей и редактуры; образцы не задают стиль нового
владельца, а работа над статьёй не подключает инженерный модуль автоматически.

Модуль `engineering` (зависит от `projects`) задаёт порядок работы с кодом в
зарегистрированном проекте. Агент сначала определяет поручение: изучить,
изменить, проверить, принять или передать работу. Каждое поручение даёт только
свой результат: просьба изучить код не разрешает правки, правка — commit,
commit — push или выпуск. Правило проекта имеет постоянный ID, область,
инвариант и способ проверки. Для нетривиальной задачи агент заполняет карточку:
что улучшить, какое наблюдаемое поведение сохранить и чем это проверить.
Review выносит вердикт по каждому правилу с доказательством и отдельно ищет
поведение, которое тесты часто не видят: порядок очистки, порядок ошибок,
освобождение ресурсов. Итог разделяет состояния «исправлено», «измерено»,
«потребители проверены», «влито», «выпущено» вместо одного слова «готово».

Модуль `experiments` описывает замеры: режим гипотезы (около 5 минут), итоговую
проверку (около часа) и долгое исследование только по явной просьбе.
Корректность проверяется до замера времени, критерий задаётся до запуска,
неудобные ячейки не удаляются, повтор без новой причины не допускается.
«Разница не установлена» — допустимый результат. Пресет `engineering`
подключает `projects`, `search`, `engineering` и `experiments`. Регистрация выполняется через `projects create` с явным выбором storage;
она создаёт карточку и навигацию. Правила создаются по отдельному поручению
в разделе, разрешённом через `projects resolve --section rules`.
`location_mode` не определяет адрес правил. Общий workflow, specs, бюджеты и
контракт коммитов находятся в `modules/engineering/references/`.


Очередь к выделенным машинам для подтверждающих замеров и координатор
(`machine-queue`) пока проектируются и не устанавливаются.

## Что работает, а что требует дальнейшей настройки

Точные ID, статусы и зависимости: [modules/registry.json](modules/registry.json).

| Возможность | Состояние |
|---|---|
| Установка, выбор модулей, проверка целостности | Локальные команды |
| Память, исправления, удаление активной записи | Локальные команды и правила агента |
| Тематические записи и контекст текущих дел | Локальное хранение; классификация и актуализация агентом |
| Техническое письмо и редактура | Выбираемый экспериментальный модуль |
| Описание IT/дизайн-проектов и иерархии правил | Локальные команды и правила агента |
| Инженерная работа: поручения, review, приёмка, передача | Правила агента и шаблоны |
| Замеры и эксперименты в бюджете | Правила агента и шаблоны |
| Поиск и архив текстов | Локальные команды; доступные чаты — workflow с отдельным выбором и инструментами среды |
| Снимок базы, очередь изменений | Локальные команды; без сетевой доставки |
| GitLab/GitHub, облачная синхронизация | Инструкции по отдельной настройке |
| Обмен навыками, управление компьютером, хранилище секретов | Необязательные инструкции; сервисы не подключены |
| Очередь к машинам для замеров и координатор | Проектирование, не реализованы |
| Удалённый MCP с телефона и других устройств | Проектирование, не реализован |

Операции installer и legacy CLI записывают события в локальную очередь; каталог проектов и навыков хранит своё актуальное состояние в карточках и реестрах. Она не означает отправку
в GitLab. Файлового наблюдателя, автоматического фонового push и сервера здесь
нет. Снимок не зашифрован; `local/` и `inbox/` в него не входят. Очередь после
снимка не очищается как будто данные доставлены удалённо. Перед архивированием
проверьте содержимое: простой детектор узнаёт лишь часть текстовых секретов и
не проверяет произвольные бинарные вложения. Снимок не является атомарным
снимком параллельно меняющегося диска; делайте его между изменениями.

`assets/` предназначена для обычных файлов. Токены не сохраняются туда или в
Markdown: используйте системное хранилище либо исключённую `local/secrets/`.
Для удобного резервирования секретов сначала отдельно настраивается настоящее
шифрование, затем пользователь разрешает синхронизацию шифротекста. Приватный
GitLab не заменяет шифрование. Отзыв памяти не удаляет старые резервные копии
автоматически. Входящий навык сначала попадает в `inbox/`, проверяется и только
после отдельного решения может быть активирован.

## Сопровождение и проверка

```sh
python3 bootstrap/scripts/jarvis.py --help
python3 -m unittest discover -s tests -v
```

Модель не ограничивается жёстким списком названий: её пригодность оценивается
сценариями. Ошибки в контексте, сохранении исправлений и разрешениях требуют
более сильной модели или меньшей автономности. Результаты независимых испытаний
и их границы: [reports/README.md](reports/README.md).

Обновление сохраняет пользовательские данные и отказывается перезаписывать
изменённые управляемые файлы. Отключение модуля удаляет его управляемые инструкции
и копию для обнаружения, сохраняя знания и локальные навыки. Несколько файлов
не образуют единую транзакцию при сбое питания; перед обновлением нужна копия.
Настоящие системы и аккаунты в этом прототипе не мигрируются.

## Проекты и группы

Карточки schema 2: [контракт](core/projects.md), [навык управления](modules/projects/SKILL.md). Проекты и группы имеют одинаковые разделы; родитель и storage независимы от исходников. CLI: `python3 bootstrap/scripts/jarvis.py projects --root ROOT --help`. Перед записью использовать resolve; без root.json и без молчаливого fallback. Legacy schema 1 требует отдельной миграции.

Применимые общие документы могут подключаться маршрутизатором другого
владельца с сохранением их Scope; это не наследование всей соседней ветки.
`projects rules` показывает родительские точки входа, а `validate` проверяет
структуру. Полноту эффективного профиля агент проверяет по маршруту отдельно.
Материалы встреч и рабочих обсуждений хранятся в `notes/discussions/` и
`assets/discussions/` выбранного владельца по [конвенции](core/discussions.md).
Общие правила [браузеров](core/browser-and-servers.md) и
[доступов](core/access.md) применяются без импорта чужих настроек или credentials.

## Навыки и автоматизации

`core/skills.md` задаёт одного владельца и оригинал каждого навыка. Реестр
`config/skill-bindings.json` содержит источники и производное discovery.
Поставляемые модули имеют управляемые копии; собственные навыки подключаются
ссылками через `skills --root ROOT register|update|sync|audit`.
Модуль `skill-management` (зависит от projects) содержит процедуру сопровождения.
Установка не меняет home discovery или настройки клиента без поручения.

`doctor` сверяет управляемые файлы, карточки проектов, доступность назначенных
корней и зарегистрированное discovery. Он не проверяет смысл каждого правила
или выбор навыка моделью. Обнаружение нужно отдельно проверить в новом чате.
Snapshot пропускает зарегистрированные производные ссылки и сохраняет их реестр;
после восстановления выполнить `skills --root ROOT sync`. Внешние оригиналы и
разделы требуют собственного резервирования.

`core/automations.md` описывает переносимые task/state и привязку к одному
исполнителю. Шаблоны лежат в templates. Пустой каталог, служба, расписание,
аккаунт или поручения другого владельца не создаются.

Общие правила перенесены из актуального Jarvis с адаптацией к новому владельцу.
Состав и допустимые отличия зафиксированы в `bootstrap/port-manifest.json`.
Пути, личные данные, Git-разрешения и настройки машин исходного экземпляра
в дистрибутив не входят. Актуальная проверка выпуска:
[отчёт](reports/2026-11-08-publication/README.md). Исторические модельные
испытания сохраняют прежнюю область проверки.
