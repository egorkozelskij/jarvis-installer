# Общие требования к коммитам

### JARVIS-COMMIT-001 — Коммит описывает выполненное изменение

- Scope: `jarvis/*` — разрешённые Git-коммиты в точном repository scope.
- Invariant: сообщение фиксирует завершённый результат текущего commit, а не будущую задачу. Перед фиксацией проверяются staged diff, границы repository, разрешение и отсутствие чужой работы. Язык и специальные форматы задаёт владелец repository.
- Safe path: проверить точный состав изменений, сохранить Conventional Commit prefix при его использовании, сформулировать фактический итог; явно отличать commit от push, release и deploy. Уже данное разрешение действует только в своём scope.
- Запрещено: включать невыполненные планы, скрывать scope, присоединять чужой WIP или считать разрешение на commit разрешением на публикацию.
- Evidence: `hard-contract` — staged diff и фактическое сообщение в точном repository. Проверка сообщения не требует новых тестов.
