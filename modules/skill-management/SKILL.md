# Управление навыками Jarvis

Прочитай `core/projects.md`, `core/skills.md`, профиль нужной группы/проекта и правила клиента, в котором должен обнаруживаться навык. У навыка один оригинал. Наличие ссылки в клиенте не делает её владельцем содержимого.

Команды ниже относятся к установленной базе; из дистрибутива укажи `skills --root ROOT` перед командой. Для нового навыка выбери владельца: весь Jarvis, группа или проект. Если пользователь не назвал владельца и место оригинала, предложи глобальный или локальный вариант по контексту и спроси; его выбор сохраняется. Не требуй повторного согласования уже названного места. Глобальный оригинал живёт в `skills/<id>` либо в разрешённом разделе `projects/<id>/skills/<skill-id>`. Локальный оригинал живёт по зарегистрированному root, обычно в `source/.agents/skills/<id>`. Точную привязку каждого навыка внеси в `config/skill-bindings.json`; только карточки проектов определяют владельца и цепочку правил.

При создании и существенном редактировании используй доступный `skill-creator`: ясные `name` и `description`, узкий workflow, нужные references/scripts/assets. Не копируй общие правила в каждый навык. Редактируй оригинал, сохраняя чужие WIP и существующие поля метаданных. При переносе скопируй и сравни содержимое источника и назначения, вызови `python3 bootstrap/scripts/skills.py update` с новой привязкой, перепроверь зависимости и только затем удали старый оригинал. При переименовании обнови запись, frontmatter, ссылки и упоминания. Удаление проверяет все ссылки и зависимости; не считай удаление текущего файла стиранием Git history и архивов.

После изменения вызови `python3 bootstrap/scripts/skills.py audit`. Для подключения вызови `sync`; он создаёт только недостающие ссылки и отказывает при чужом файле или ссылке. Обнаружение Codex: `.agents/skills` в repo или home, а в этой установке также используемая `~/.codex/skills`. Не подключай один навык в два одновременно сканируемых места. Глобальный навык размещай в пользовательском discovery; навыки группы — в корне соответствующего repo; узкие — в repo проекта. Для проекта без исходной папки используй пользовательский discovery и явно ограничь область применения в `description`. Самостоятельный вложенный checkout может требовать отдельной ссылки. Новые discovery paths и другие клиенты проверяй по их актуальной документации, не переноси Codex-правило автоматически.

Перед завершением проверь, что каждый установленный путь разрешается в один оригинальный `SKILL.md`, имя уникально среди активных навыков, а пользователь видит нужный навык после обновления discovery. Если клиент не обновился автоматически, перезапусти его по документации. Не выдавай наличие ссылки за подтверждение выбора навыка моделью.

Управляемые модульные копии с `managed_module` обновляются установщиком, не командами register/update. До удаления или переноса пользовательского оригинала проверь связанные проекты. Команды не создают навыки из описания и не поручают регистрацию новых проектов.
