# Перенос общих правил Jarvis

Дата: 2026-10-29. Поручение: перенести переиспользуемые правила центрального Jarvis в дистрибутив.

## Карточка задачи

- Цель: установленная база получает общий порядок общения, критической оценки, ведения тематической памяти и текущих дел; автоматическая память и сбор доступных чатов включаются явным выбором владельца.
- Scope: `core`, выбранные модули, bootstrap, адаптеры и пользовательские руководства `jarvis-installer`.
- Сохранить: существующий WIP, значения по умолчанию `on-request`/`ask`, прежние CLI-команды и расположение старых заметок; разделение linked/embedded проектов, проверки путей, разрешений и секретов.
- Контракты: общие правила применяются по scope; у знания один основной источник; выбор памяти не разрешает внешние действия и не устанавливает фоновый сервис.
- Проверка: синтаксис Python и JSON, локальные ссылки и маршруты, состав diff относительно сохранённой рабочей копии. Тесты, пробные установки и модельные испытания без отдельной просьбы не запускаются.
- Результат: локальные правки и точное описание возможностей и оставшейся проверки.
- Бюджет: одна ограниченная серия переноса и статической проверки; расширение до коннекторов, сервиса, миграции или релиза не входит.
- Не разрешено: commit/push инсталлера, теги, публикация, deploy, реальные аккаунты, глобальные настройки или импорт личных данных владельца.

## Выполнено

- В `core` перенесены общение с сохранением нити нумерованного обсуждения, критическая оценка решений, иерархия документов, актуализация затронутых маршрутов и передача длительной работы. Инструкции не добавляют внешних полномочий.
- `auto` стал явным режимом сохранения значимых фактов, предпочтений, решений и текущего состояния самим общающимся агентом, когда это обоснованно полезно для будущего общения или работы. `on-request`/`ask` остались начальными вариантами, в том числе в примере ответов.
- `note` и `forget` получили `--section`; старые вызовы по-прежнему используют `notes`, прежние пути истории исправлений сохранены. Новые разделы имеют отдельную историю исправлений. Добавлены виды state, event, hypothesis и question.
- При выбранной личной памяти один раз создаётся пустой указатель `context/active.md`. Это пользовательские данные: обновление не перезаписывает существующий файл, отключение модуля его не удаляет. Остальные тематические разделы создаются при записи.
- История имеет отдельный выбор `provided-only`/`available-chats`. Старые текстовые параметры сохраняют поведение импорта предоставленных файлов. Для доступного чата CLI принимает источник, ID и дату и сохраняет отдельный фрагмент по hash. Повтор одинакового фрагмента сохраняет первый импорт и не создаёт новое событие; отбор новых ID сообщений и указатели покрытия принадлежат workflow агента.
- Добавлен выбираемый экспериментальный модуль `writing` с редакционными материалами. Удалены утверждения о предпочтениях и одобрении образцов прежним владельцем. Discovery-копия модуля включает справочные файлы вместе с SKILL.md; нормативный источник остаётся в `modules`.
- Согласованы русское и английское руководства, bootstrap и адаптеры. Глобальные пути, аккаунты, личные данные, разрешения на Git и существующее расписание в дистрибутив не переносились.

## Проверка и границы

- Python разобран через AST; JSON реестра и примера ответов прочитан, ID и зависимости модулей согласованы.
- Локальные Markdown-ссылки новых/затронутых маршрутов и frontmatter навыков проверены. Новые переносимые материалы просмотрены на персональные пути, ID и разрешения.
- Команды `questions` для ru/en и `note`/`forget`/`archive --help` прочитаны без установки и записи пользовательских данных. Наборы вопросов согласованы; новые параметры присутствуют.
- `git diff --check` прошёл. Изменения сопоставлены с рабочей копией, сохранённой перед переносом; существующие tests и артефакты review-trial не менялись этой задачей. Index не изменялся.
- Тесты, пробная установка, обновление существующей базы, cold discovery, модельные испытания и реальные коннекторы не запускались. Их прохождение не заявляется; прежние отчёты не являются evidence нового поведения.
- Код и документы оставлены локальными изменениями. Commit/push инсталлера, релиз и deploy не выполнялись. В рабочей копии сохраняется WIP, существовавший до этой задачи.

Следующая проверка при отдельном поручении: установка на синтетических данных,
сохранность пользовательского указателя при обновлении/отключении, тематические
исправления и удаление, запрет capture без выбора, повторный импорт и комплектность
discovery. Подключение аккаунтов и расписания остаётся отдельной настройкой экземпляра.

## Уточнение механизма памяти

В core, модуле памяти, истории, bootstrap, адаптерах, обоих руководствах и
генерируемом AGENTS закреплено: запись решает и выполняет сам агент текущего
разговора, когда находит её пользу для дальнейшего общения или работы.
Новое сообщение, завершение ответа и истечение времени сами по себе не требуют
записи. Планировщик, периодический обход чатов и отдельный фоновый агент не
подменяют это решение. Из workflow памяти убраны предложения о почасовом запуске.
Существующие функции тематического хранения и явные варианты настройки сохранены.
