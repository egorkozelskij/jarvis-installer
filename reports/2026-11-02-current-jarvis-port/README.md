# Перенос актуальных контрактов Jarvis — 2 ноября 2026

Поручение владельца: доработать Installer в соответствии с текущим глобальным
Jarvis. Версия рабочей копии и оба руководства согласованы на 0.4.0.
Это локальная реализация, не публичный релиз: origin/main остаётся 0.1.0,
commit 44af187dd583c179b86192e497f107d47161afac.

## Выполнено

- Сохранён исходный WIP, перед правками сделана внешняя временная копия.
  Исторические ответы моделей и fixtures не изменены. Индекс отчётов дополнен ссылкой; runner подготовки адаптирован к schema 2 без запуска моделей.
- Убраны старые зависимости хранения rules от folder/shared. Schema 2,
  родитель, sources и storage выбирают адреса независимо от location_mode.
- Добавлены общий workflow, спецификации, бюджеты проверок/отчётов и контракт
  коммитов. Experiments ссылается на одного владельца нормативных бюджетов.
- Волны, HANDOFF, разделение координатора и исполнителей и ограниченное ожидание
  согласованы с общими rule IDs. Не перенесено утверждение о стоимости шага
  по одной длине контекста. Разрешения на делегирование и проверки сохранены.
- Тематические note/forget реально используют --section. Разные разделы могут
  иметь одинаковый ID; исправления сохраняют прежнее состояние отдельно.
  Коррекция проектной записи не оставляет два конкурирующих текущих факта.
- Structured archive использует provider/chat/date, требует available-chats,
  проверяет ID/дату, сохраняет первый импорт и не создаёт повторное событие.
  Проектный архив использует назначенный assets, включая внешнее хранение.
- Добавлены реестр оригиналов навыков, register/update/sync/audit и выбираемый
  skill-management. Управляемые модульные копии явно обозначены производными;
  пользовательские оригиналы подключаются ссылками. Изменения сериализованы
  installation lock; чужой файл не перезаписывается, корни и owner проверяются.
- Doctor проверяет hashes, карточки, доступность назначенных корней/источников
  и зарегистрированное discovery. Это структурная проверка, не модельная приёмка.
- Snapshot сохраняет реестр, пропускает зарегистрированные производные ссылки,
  не выдаёт внешнее хранилище за скопированное. Тематический personal/inbox
  сохраняется как знания; исключения /local и /inbox относятся к корню instance.
- Перенесён общий контракт task/state автоматизаций с шаблонами. Службы,
  аккаунты, реальные задачи и расписания не создаются.
- В bootstrap/port-manifest.json записаны 36 исходных контрактов, fingerprints
  и осознанные переносимые отличия. check_port.py — read-only проверка дрейфа
  по явно переданному исходному Jarvis, без watcher и автоматической синхронизации.

Правила конкретных проектов Endge, личные данные, host paths, токены,
расписания и standing Git-разрешения исходного владельца не переносились.

## Проверка

`python3 -B -m unittest discover -s tests -p test_installer.py -v`:
**37 тестов прошли**, итоговая серия 5.844 секунды, macOS.

Проверены новая установка и обновление с фактического опубликованного снимка
0.1.0 на синтетических данных, сохранение пользовательских знаний и настроек,
конфликты управляемых файлов, lock, тематические исправления/удаление,
наследование, смешанное хранение и недоступный root без fallback, перенос
раздела с удержанием исходника до finalize, consent и дедупликация архива,
регистрация/обновление навыка, чужой discovery-файл и snapshot.

Старые ожидания создания проектов заменены актуальными сценариями schema 2;
legacy-чтение проверяется отдельно, старые данные не мигрируются автоматически.
Новые сценарии проверяют результат на диске и сохранность данных. Отдельно проверена подготовка review-фикстуры на новом CLI: модели не запускались, answer/events не создавались.

Дополнительно: AST Python, JSON, локальные Markdown-ссылки, git diff --check,
skill-creator quick_validate для skill-management и check_port по 36 контрактам
прошли. Последний check_port вернул ok=true, issues=[].

## Границы

Реальная база владельца не переустанавливалась, пользовательские проекты не
мигрировались. Новые модельные испытания, cold host discovery и Windows/Linux
runtime не выполнялись. Исторические испытания остаются историческими.
Commit/push Installer, теги, GitHub Release и deploy не выполнялись.
Перед публичным выпуском нужен отдельный разрешённый выпуск рабочего дерева;
это поручение не является разрешением публикации.
