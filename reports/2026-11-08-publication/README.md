# Проверка снимка перед публикацией 0.4.0 — 8 ноября 2026

Источник: поручение владельца в текущем чате — опубликовать Installer по его
правилам после согласования коммита. Предлагаемое сообщение:
`chore(release): v0.4.0`. Этот отчёт фиксирует подготовку и проверки снимка;
сам по себе он не подтверждает создание коммита или отправку на GitHub.

## Состав

- Карточки проектов и групп schema 2, независимые sources/storage, разрешение
  разделов и цепочки родителей, сохранение legacy-данных до отдельной миграции.
- Тематическая память, текущие дела и архив доступных чатов с отдельным выбором
  владельца; оригиналы навыков, discovery и переносимые task/state автоматизаций.
- Модули engineering, experiments, writing и skill-management; исторические
  инженерные review-фикстуры, задания и ответы для воспроизведения.
- Последние уточнения явных common-маршрутов и границ CLI rules/validate,
  рабочие обсуждения с неизменными исходниками, уборка браузерных ресурсов и
  порядок выбора доступов независимо от cwd. Удалена устаревшая ссылка на
  задачи прежнего портала из итогового инженерного workflow.
- Русское и английское руководства объясняют подключение точки входа к клиенту,
  которое установка не выполняет автоматически.

Последний перенос сверяется по 39 контрактам в
`bootstrap/port-manifest.json`: hash исходного и поставляемого файла, режим
идентичного переноса или адаптации. Source HEAD указан для происхождения;
фактический снимок определяется hashes рабочего дерева, а не предположением
о его чистоте. В `core/access.md` перенесён порядок работы с ресурсами, а не
личный каталог доступов. Личные сведения, исходные проекты, machine profiles,
аккаунты, credentials, host settings и standing Git permissions не входят.

## Проверки этого снимка

- `python3 -B -m unittest discover -s tests -p test_installer.py -v`:
  **37 passed**, 0 failed, 6.796 секунды на macOS. Проверки используют
  вымышленные данные во временных каталогах, включая установку и обновление
  с опубликованного снимка 0.1.0, сохранение знаний, locks, конфликты,
  тематические исправления, проектные bindings и discovery.
- `check_port.py --source <явно указанный исходный Jarvis>`: 39 файлов,
  `ok=true`, `issues=[]`.
- Python проверен парсером с грамматикой 3.10; JSON и локальные Markdown-ссылки
  руководств и устанавливаемых материалов проверены отдельно. Ссылки внутри
  исторических ответов моделей сохранены дословно: часть указывает на удалённые
  временные TEST_ROOT и исходные строки фикстур. Это не навигация установки.
  Полный `git diff --cached --check` отмечает восемь ожидаемых строк: два
  Markdown hard-break в `natural-technical-writing.md` и шесть строк контекста
  unified diff в `review-trial-hard/candidate.patch`. Они сохранены, чтобы не
  менять разметку и применимость фикстуры. Для остальных файлов проверка чистая.
- В устанавливаемых материалах не найдены известные абсолютные пути и адреса
  исходного владельца; поиск распространённых форматов credentials не нашёл
  совпадений. Это ограниченная проверка состава, а не универсальный детектор
  секретов.

## Публикация и границы

При подготовке `origin/main` указывает на
`44af187dd583c179b86192e497f107d47161afac` (0.1.0). Локальный `main` содержит
ещё не отправленный commit `7b8cf23e2ec87e2827fb714229ad9100a6465b22`
(`chore(release): v0.2.0`). Обычный push после согласованного нового коммита
0.4.0 опубликует оба коммита без переписывания истории. Полный состав
подготовленного коммита должен быть показан владельцу до фиксации.

Поручение относится к публикации исходников Installer. Статья находится
в другом репозитории и в этот коммит не включается. Новые модельные прогоны,
Windows/Linux runtime, холодное обнаружение навыков приложениями и реальные
внешние сервисы не проверялись. Реальная база владельца не переустанавливалась,
пользовательские проекты и глобальная конфигурация клиентов не изменялись.
Исторические отчёты не выдаются за новые проверки.
